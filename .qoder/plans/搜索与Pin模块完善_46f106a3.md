## 二、分任务实现方案

### Task 1: 原始搜索框集成与模式切换（需求2）

**问题**: 当前原始 Perfetto 顶部 Omnibox 仍然独立显示，新侧边栏搜索框与之无交互。

**方案**:

1. **在新搜索框右侧添加"原始搜索"切换按钮**
   - 文件: `ui/src/plugins/org.openperfetto/sidebar/search_pin.ts`
   - 添加 `useOriginalSearch: boolean` 状态，默认 `false`
   - 搜索框右侧增加一个 toggle 按钮（图标 `swap_horiz` 或 `find_in_page`）
   - 选中时搜索框变为代理原始 Omnibox 功能

2. **代理原始搜索功能**
   - 当 `useOriginalSearch = true` 时：
     - 输入文本通过 `trace.search.search(text)` 调用原始搜索逻辑（即 `SearchManagerImpl`）
     - 搜索结果通过 `trace.search.searchResults` 读取
     - 渲染 stepthrough 导航（前进/后退按钮 + 结果计数）
     - 保持原始搜索的加载进度显示（检查 `trace.search.searchInProgress` 显示 Spinner）
   - 当 `useOriginalSearch = false` 时：保持当前新搜索逻辑（SQL 查进程/线程）

3. **隐藏原始顶部 Omnibox**（需求要求"原始Perfetto顶部的搜索框不再顶部显示"）
   - 文件: `ui/src/plugins/org.openperfetto/styles/openperfetto.scss`
   - 当 OpenPerfetto 侧边栏激活时，通过 CSS 隐藏 `.pf-topbar` 中的 Omnibox
   - 使用 `body.openperfetto-active .pf-omnibox { display: none; }` 或类似选择器
   - 注意：需要在 `index.ts` 的 `onActivate` 中给 body 添加 class

4. **加载进度集成**
   - 在新搜索框中，trace 加载时显示 loading 状态
   - 监测 `trace.search.searchInProgress` 状态在搜索框内显示 Spinner 组件

**关键代码改动点**:
```typescript
// search_pin.ts - 新增状态
private useOriginalSearch: boolean = false;

// 渲染切换按钮
m(Button, {
  icon: this.useOriginalSearch ? 'find_in_page' : 'manage_search',
  onclick: () => { this.useOriginalSearch = !this.useOriginalSearch; },
  title: this.useOriginalSearch ? '原始搜索模式' : '新搜索模式',
  compact: true,
})

// 原始搜索模式下的搜索逻辑
if (this.useOriginalSearch) {
  trace.search.search(this.searchQuery);
}
```

### Task 2: Ctrl+F 快捷键拦截（需求3）

**问题**: 当前 Ctrl+F 使用浏览器默认搜索或被 Perfetto Omnibox 处理，新搜索模块未接管。

**方案**:

1. **在插件 `onActivate` 中注册全局 keydown 监听器**
   - 文件: `ui/src/plugins/org.openperfetto/index.ts`
   - 监听 `document` 上的 `keydown` 事件
   - 当检测到 `Ctrl+F`（Windows）/ `Cmd+F`（Mac）时：
     - `e.preventDefault()` 阻止浏览器默认搜索
     - 如果侧边栏关闭则打开侧边栏
     - 聚焦新搜索框输入框

2. **为搜索框添加 ref 机制以支持外部聚焦**
   - 文件: `ui/src/plugins/org.openperfetto/sidebar/search_pin.ts`
   - 使用 `oncreate` 钩子保存输入框 DOM 引用
   - 暴露 `focusSearchInput()` 静态方法或通过全局事件通信

**关键代码改动点**:
```typescript
// index.ts - onActivate 中
document.addEventListener('keydown', (e: KeyboardEvent) => {
  if ((e.ctrlKey || e.metaKey) && e.key === 'f') {
    e.preventDefault();
    if (sidebarState === 'closed') openSidebar();
    // 触发搜索框聚焦
    SearchPin.focusInput();
  }
});
```

### Task 3: 搜索历史完善（需求4）

**问题**: 
- 点击历史项仅填充搜索框，不触发搜索
- 长文本无缩略显示和 tooltip

**方案**:

1. **点击历史即搜索**
   - 文件: `ui/src/plugins/org.openperfetto/sidebar/search_pin.ts`
   - 修改 `renderSearchHistory` 中的 onclick 回调：填充后立即调用 `this.doSearch(trace)`
   - 需要将 `trace` 传入 `renderSearchHistory` 方法

2. **文本缩略 + tooltip**
   - 文件: `ui/src/plugins/org.openperfetto/sidebar/search_pin.ts`
   - 历史项 `span` 添加 CSS class `openperfetto-search-pin__history-text`
   - CSS: 设置 `max-width`、`overflow: hidden`、`text-overflow: ellipsis`、`white-space: nowrap`
   - HTML: 添加 `title` 属性显示完整文本

3. **搜索历史改为始终显示（非仅 focus 时）**
   - 根据需求"搜索框下面是搜索历史功能"，历史应该作为固定区域显示，而非下拉
   - 移除 `showHistory` 状态和 focus/blur 逻辑
   - 改为固定渲染在搜索框下方

**关键代码改动点**:
```typescript
// search_pin.ts - renderSearchHistory 修改
private renderSearchHistory(trace: Trace, locale: 'zh' | 'en'): m.Children {
  return m('.openperfetto-search-pin__history', [
    m('.openperfetto-search-pin__history-header', ...),
    this.searchHistory.map((query) =>
      m('.openperfetto-search-pin__history-item', {
        onclick: () => {
          this.searchQuery = query;
          this.doSearch(trace);  // 关键：立即触发搜索
        },
        title: query,  // tooltip 显示完整文本
      }, [
        m(Icon, {icon: 'history'}),
        m('span.openperfetto-search-pin__history-text', query),
      ])
    ),
  ]);
}
```

SCSS 新增:
```scss

  max-width: 180px;
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
  display: inline-block;
```

### Task 4: 预置Pin场景完善（需求5）

**问题**:
- 应用预置时无法匹配的线程没有提示
- Settings 中无拖拽排序
- Settings 面板 Presets CRUD 功能需确认完整性

**方案**:

1. **失败提示通知**
   - 文件: `ui/src/plugins/org.openperfetto/sidebar/search_pin.ts`
   - `applyPreset` 方法中，对每个 thread 记录是否匹配成功
   - 匹配失败的收集到 `failedThreads` 数组
   - 应用完成后，如有失败项，显示临时通知消息（2-3秒自动消失）
   - 新增 `notification` 状态 + 渲染逻辑

```typescript
// applyPreset 修改
private async applyPreset(trace: Trace, preset: PresetPinScene): Promise<void> {
  const failedThreads: string[] = [];
  for (const threadConfig of preset.threads) {
    // ... SQL 查询 ...
    const found = /* check if utid found */;
    if (!found) {
      failedThreads.push(`${threadConfig.processPattern}+${threadConfig.threadPattern}`);
    }
  }
  if (failedThreads.length > 0) {
    this.showNotification(`未找到: ${failedThreads.join(', ')}`, 3000);
  }
}
```

2. **拖拽排序**
   - 文件: `ui/src/plugins/org.openperfetto/sidebar/settings.ts`
   - 在 Presets 编辑界面中，为线程规则列表添加拖拽排序
   - 使用原生 HTML5 Drag and Drop API（`draggable`, `ondragstart`, `ondragover`, `ondrop`）
   - 不引入外部拖拽库，保持轻量
   - 拖拽后更新 `order` 字段并 re-render

**关键改动**:
- settings.ts: 线程规则列表项添加 `draggable: true`
- 实现 `dragStart`, `dragOver`, `drop` 事件处理器
- openperfetto.scss: 添加拖拽相关样式（拖拽中项半透明、drop 位置指示线）

### Task 5: AI 置顶标识（需求6）

**问题**: AI 通过 `PinThreadTool` pin 的轨道没有视觉标识，与用户手动 pin 无法区分。

**方案**: 这个需求需要修改 Perfetto 核心的 track 渲染逻辑，比较侵入性强。建议分两步：

1. **状态层：记录 AI pin 的轨道**（当前已有 `AIPinnedTrack` 类型）
   - 文件: `ui/src/plugins/org.openperfetto/tools/pin_thread.ts`
   - pin 成功后，将 track 信息写入 `state.currentSession.pinnedTracks`
   - 提供 `isAIPinned(trackUri: string): boolean` 查询方法

2. **UI层：在置顶轨道上显示 AI 图标**
   - 方案A（推荐，低侵入）：通过 DOM Mutation 在 pinned 轨道的 title 元素前注入 AI 图标
   - 方案B（高侵入）：修改 Perfetto 核心 track_panel.ts，不推荐
   - 方案A 实现：在 `index.ts` 的 `onTraceLoad` 后，使用 `MutationObserver` 监听 workspace 变化，当检测到 AI pinned track 的 DOM 出现时，注入 `<span class="ai-pin-badge">` 图标

3. **API 预留**
   - 文件: `ui/src/plugins/org.openperfetto/tools/pin_thread.ts`
   - 确保 `PinThreadTool.execute()` 返回结果中包含 `aiPinned: true` 标记
   - 在 state 中维护 `aiPinnedTrackUris: Set<string>`
   - 提供 `unpinAITrack(trackUri)` 方法供用户取消 AI 标记

**注意**: 此需求在实现规范中标记为"需要预留接口"，建议先完成状态管理和 API 预留，视觉标识可以用 MutationObserver 方式注入，后续优化。

## 五、风险点

1. **隐藏原始 Omnibox 的影响**：原始 Omnibox 还承载了命令模式 (`>`)、提示模式等功能。隐藏后需确保这些功能可通过新搜索框或其他途径访问。建议：仅在"新搜索模式"下隐藏，切换到"原始搜索模式"时恢复显示，或者通过代理完整转发。 -- 通过代理完整转发，切换到"原始搜索模式"时不恢复显示。需要确保原始 Omnibox 功能无异常。
2. **AI 图标注入的稳定性**：MutationObserver 方式依赖 DOM 结构，Perfetto 版本更新可能导致选择器失效。
3. **Ctrl+F 拦截**：某些浏览器/场景下 `e.preventDefault()` 对 Ctrl+F 的拦截可能不完全生效。
