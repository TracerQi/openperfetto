# 项目文件夹重命名方案：perfetto -> openperfetto

## 分析结论

经过全面扫描，项目中 "perfetto" 的引用分为三大类：

### 不需要修改（构建系统模块名/品牌标识）
- **Bazel 模块名**：`MODULE.bazel` 中 `module(name = "perfetto")`、`WORKSPACE` 中 `workspace(name = "perfetto")`、`.bazelrc` 中 `@perfetto//bazel:...` -- 这些是构建系统的公共API标识符，与文件夹名无关，GN/Bazel 使用 `//` 表示源码根目录
- **GN 变量名**：`perfetto_root_path`、`enable_perfetto_*`、`perfetto_build_*` 等 -- 约定俗成的命名，值为 `"//"` (相对路径)，不依赖文件夹名
- **Python 包名**：`setup.py` 中 `name='perfetto'` -- 上游包名
- **前端包名**：`ui/package.json` 中 `name: "perfetto-webui"` -- 前端包标识
- **品牌引用**：`perfetto.dev`、`Google Perfetto`、源码中的消息协议字段名
- **CI/CD 配置**：GCS 桶名、CIPD 包名、测试目标名

### 需要修改（硬编码绝对路径）

**影响文件共 13 个**：

| 文件 | 问题 |
|------|------|
| `run_build.sh` | 4 处 `/mnt/d/1aLq/ProFile/perfetto` 硬编码路径 |
| `start_frontend.sh` | 5 处硬编码路径 |
| `restart_dev_server.sh` | 3 处硬编码路径 |
| `kill_build.sh` | 1 处硬编码路径 |
| `debug_stdlib.sh` | 2 处硬编码路径 |
| `tmp/backend_dev.sh` | 1 处硬编码路径 |
| `tmp/backend_build.sh` | 1 处硬编码路径 |
| `tmp/backend_install.sh` | 1 处硬编码路径 |
| `tmp/install_deps.sh` | 1 处硬编码路径 |
| `tmp/setup_buildtools.sh` | 2 处硬编码路径 |
| `tmp/setup_gn_ninja.sh` | 2 处硬编码路径 |
| `docs/openperfetto/quick-rebuild.md` | 约 30+ 处路径引用 |
| `docs/openperfetto/deployment.md` | 约 15+ 处路径引用 |
| `docs/openperfetto/shutdown-guide.md` | 约 6 处路径引用 |

## 修改策略

**核心思路**：不做简单的字符串替换（`perfetto` -> `openperfetto`），而是将脚本改为**使用相对路径**，这样既解决重命名问题，又提升开源后的可移植性（其他开发者克隆到任意目录都能工作）。

---

## Task 1：改造根目录脚本为相对路径（5 个文件）

所有根目录脚本统一使用 `SCRIPT_DIR` 模式自动定位项目根目录：

```bash
SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
```

**涉及文件**：
- `run_build.sh`：将 `LOCKFILE=/mnt/d/1aLq/ProFile/perfetto/out/ui/watch.lock` 改为 `LOCKFILE="$SCRIPT_DIR/out/ui/watch.lock"`，`cd` 和 `export PATH` 同理
- `start_frontend.sh`：同上，所有 `/mnt/d/1aLq/ProFile/perfetto` 替换为 `$SCRIPT_DIR`
- `restart_dev_server.sh`：同上
- `kill_build.sh`：`rm -f /mnt/d/1aLq/ProFile/perfetto/out/ui/watch.lock` 改为 `rm -f "$SCRIPT_DIR/out/ui/watch.lock"`
- `debug_stdlib.sh`：同上

## Task 2：改造 tmp/ 目录脚本（6 个文件）

`tmp/` 目录下的脚本同样改为相对路径模式：

- `tmp/backend_dev.sh`、`tmp/backend_build.sh`、`tmp/backend_install.sh`：`cd` 路径改为 `$SCRIPT_DIR/../server`
- `tmp/install_deps.sh`：`cd` 路径改为 `$SCRIPT_DIR/..`
- `tmp/setup_buildtools.sh`、`tmp/setup_gn_ninja.sh`：`PERFETTO` 变量改为 `$SCRIPT_DIR/..`

## Task 3：更新文档中的路径引用（3 个文件）

文档中的路径有两种处理方式：
1. **脚本调用命令**：路径改为 `<项目根目录>` 占位符或使用新名称 `openperfetto`
2. **WSL bash 命令示例**：由于文档面向用户，改用 `openperfetto` 作为项目目录名

**涉及文件**：
- `docs/openperfetto/quick-rebuild.md`：所有 `/mnt/d/1aLq/ProFile/perfetto` 替换为 `/mnt/d/1aLq/ProFile/openperfetto`（或用通用路径 `<PROJECT_ROOT>`）
- `docs/openperfetto/deployment.md`：同上
- `docs/openperfetto/shutdown-guide.md`：同上

> 注意：文档中的 PowerShell 命令 `wsl bash /mnt/d/1aLq/ProFile/perfetto/kill_build.sh` 这类调用，在脚本本身改为相对路径后，只要 `cd` 到正确目录，脚本就能正常工作。但 PowerShell 调用 WSL 脚本时仍需指定脚本的绝对路径，因此文档中这些路径需要更新为新目录名。

## Task 4：物理重命名文件夹

在 Windows 资源管理器或 PowerShell 中重命名：
```powershell
Rename-Item -Path "d:\1aLq\ProFile\perfetto" -NewName "openperfetto"
```

## Task 5：重命名后清理和重建

文件夹重命名后，以下产物需要清理/重建：
1. 删除 `out/ui/` 目录中的构建缓存（`.ninja_deps`、`.ninja_log` 中保存了旧绝对路径）
2. 重新安装 `ui/node_modules`（`npm install --legacy-peer-deps`）
3. 重新安装 `server/node_modules`（`npm install`）
4. 执行一次完整构建验证

## 风险评估

| 风险 | 级别 | 说明 |
|------|------|------|
| 构建系统中断 | 低 | GN 使用 `//` 相对路径，Bazel 使用模块名，均不依赖文件夹名 |
| 脚本路径失效 | 高（已处理） | 改为相对路径后完全消除此风险 |
| CI/CD 失败 | 无 | GitHub Actions 使用 checkout action，自动使用仓库名作为目录名 |
| node_modules 失效 | 中（已处理） | 重命名后重新 npm install 即可 |
| 构建缓存失效 | 中（已处理） | 清理 out/ 后重新构建 |
