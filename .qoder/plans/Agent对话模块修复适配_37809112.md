### 仍存在的 5 个阻塞问题

**问题1（P0级 - 协议Bug）：错误消息格式不匹配**
- 后端发送：`{type: 'error', data: {code: 'LLM_ERROR', message: '实际错误信息'}}`
- 前端WS映射后：`{type: 'error', payload: {code: 'LLM_ERROR', message: '实际错误信息'}}`
- LLMStreamHandler 取值：`streamMsg.payload?.error` — 但 payload 中没有 `error` 字段（只有 `code` 和 `message`）
- **后果**：所有错误消息永远显示 "Unknown error"，用户无法看到真实错误原因（如 API Key 无效等）

**问题2（P0级 - 功能阻塞）：后端未配置 ofox.ai**
- `server/config/default.yaml` 中 openai provider 没有设置 `baseUrl`，默认走 `https://api.openai.com/v1`
- 模型名称是 `gpt-4o`，ofox.ai 要求带供应商前缀如 `openai/gpt-5.4-mini`
- 环境变量 `OPENAI_API_KEY` 未设置时，LLMProxy 跳过 provider 初始化 → 进入 Echo 降级模式（只回显消息）

**问题3（P1级）：流式响应无 Usage 数据**
- `llm_proxy.ts` OpenAI Provider 请求体中缺少 `stream_options: {include_usage: true}`
- OpenAI/ofox.ai 流式模式下不主动返回 usage，导致 token 统计永远为 0
- 前端 `agent_loop.ts` L715 的 `onDone` 回调丢弃了 usage 参数

**问题4（P1级）：前端关键流程缺少结构化日志**
- `agent_loop.ts` 多处使用 `console.error/log` 而非 `opLogger`
- `websocket_client.ts` 全部使用 `console.error/warn`
- 不利于线上日志管控和调试定位

**问题5：前后端接口对齐 — 需要整体验证**
- 除了问题1的 error 格式，其余消息类型（text_delta/tool_use/done）经验证格式匹配正确
- 需在修复后做端到端验证确认

## 二、修复方案（5个Task）

### Task 1: 后端 ofox.ai API 适配

**修改文件 1**：`server/config/default.yaml`

在 openai provider 下添加 baseUrl 配置，并更新模型名称：

```yaml
llm:
  defaultProvider: "openai"
  providers:
    openai:
      apiKey: "${OPENAI_API_KEY}"
      baseUrl: "${LLM_BASE_URL:-https://api.ofox.ai/v1}"
      model: "${LLM_MODEL:-openai/gpt-4.1}"
      maxTokens: 16384
```

说明：
- `baseUrl` 通过环境变量 `LLM_BASE_URL` 控制，默认值指向 ofox.ai
- `model` 通过环境变量 `LLM_MODEL` 控制，默认值使用 ofox.ai 模型命名格式
- API Key 复用 `OPENAI_API_KEY` 环境变量（ofox.ai 兼容 OpenAI 认证格式）
- 保留 anthropic provider 配置不变

**修改文件 2**：`server/src/services/llm_proxy.ts` OpenAIProvider.chat() 方法

在请求体中添加 `stream_options` 以获取流式模式下的 usage 数据：

```typescript
// llm_proxy.ts L298-303，在 body 构建后添加
const body: Record<string, unknown> = {
  model: this.model,
  max_tokens: request.maxTokens ?? this.maxTokens,
  messages,
  stream: true,
  stream_options: { include_usage: true },  // 新增：流式模式下返回 usage
};
```

同时在 OpenAIProvider 构造函数中添加日志：

```typescript
constructor(...) {
  // ...existing code
  logger.info(`OpenAI provider initialized`, {
    model: this.model,
    baseUrl: this.baseUrl,
    maxTokens: this.maxTokens,
  });
}
```

### Task 2: 修复错误消息协议不匹配

**修改文件**：`ui/src/plugins/org.openperfetto/services/llm_stream_handler.ts` L175-178

当前代码：
```typescript
case 'error':
  this.flushTextBuffer();
  this.callbacks.onError(streamMsg.payload?.error || 'Unknown error');
  this.isStreaming = false;
  break;
```

修改为（兼容后端实际格式 `{code, message}` 和 spec 格式 `{error: '...'}`）：
```typescript
case 'error':
  this.flushTextBuffer();
  {
    const errorPayload = streamMsg.payload as Record<string, unknown> | undefined;
    const errorMsg =
      (errorPayload?.error as string) ||
      (errorPayload?.message as string) ||
      'Unknown error';
    const errorCode = errorPayload?.code as string | undefined;
    const fullError = errorCode ? `[${errorCode}] ${errorMsg}` : errorMsg;
    this.callbacks.onError(fullError);
  }
  this.isStreaming = false;
  break;
```

(c) 修改 handleAwaitingLLMState 的 LLM_DONE 分支（L520-526），将 usage 存入 session：
```typescript
case 'LLM_DONE':
  this.finalizeStreamingMessage();
  // 记录 token 使用量
  if (event.usage) {
    this.store.edit((draft) => {
      if (draft.currentSession) {
        draft.currentSession.totalInputTokens =
          (draft.currentSession.totalInputTokens || 0) + (event.usage?.inputTokens || 0);
        draft.currentSession.totalOutputTokens =
          (draft.currentSession.totalOutputTokens || 0) + (event.usage?.outputTokens || 0);
      }
    });
  }
  this.state = AgentLoopState.VERIFYING;
  this.updateProgress('验证结果...');
  m.redraw();
  await this.runVerification();
  break;
```

### Task 5: 前后端接口对齐验证

修复完成后，逐一验证以下消息类型的前后端格式匹配：

| 消息类型 | 后端发送格式 | 前端解析路径 | 状态 |

## 四、ofox.ai 接入配置说明

用户使用时需设置以下环境变量：
```bash
# ofox.ai API Key（使用 OPENAI_API_KEY 变量名，因为 ofox.ai 兼容 OpenAI 协议）
export OPENAI_API_KEY="sk-your-ofox-api-key"

# 可选：自定义 base URL（默认已指向 ofox.ai）
# export LLM_BASE_URL="https://api.ofox.ai/v1"

# 可选：自定义模型（默认 openai/gpt-4.1）
# export LLM_MODEL="openai/gpt-5.4-mini"
```

然后启动后端服务：
```bash
cd server
npm run dev   # 或 node dist/index.js
```

## 五、风险评估

| 风险 | 概率 | 缓解措施 |
|------|------|---------|
| ofox.ai SSE 格式与 OpenAI 不完全一致 | 低 | ofox.ai 官方声明完全兼容 OpenAI SDK |
| stream_options 参数不被 ofox.ai 支持 | 低 | 该参数为可选，不支持时不影响主流程，仅 usage 为空 |
| 环境变量未设置导致空 apiKey | 中 | 后端已有 apiKey 空检查跳过逻辑 + Echo 降级 |
